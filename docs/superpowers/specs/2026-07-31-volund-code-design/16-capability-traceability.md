# Volund CLI capability traceability baseline

This document freezes the evidence baseline used by the R0–R6 roadmap. It deliberately does not inherit completion from historical issues or from the checkmarks that used to appear in `10-milestones.md`.

## Audit baseline and rules

- Repository baseline: `origin/main@74723303c8b4a020834ed0edb1e3113ce6d5d23c` (frozen 2026-08-10).
- Scope: every normative design chapter in this directory, the sandbox and provider-plugin supplements, L1–L5/v2 decisions, implementation entry points, direct tests, workflows, release evidence, changesets, and historical APO issues.
- Allowed states: `missing`, `partial`, `implemented-unwired`, `verified-local`, `verified-ci`, `external-pending`, `release-ready`.
- A type, fixture, mock, dry-run, UI label, changeset, merged PR, or closed issue is evidence of that artifact only. It does not prove a user-visible capability.
- `verified-local` requires a real runtime path plus a direct test on the frozen SHA. `verified-ci` additionally requires a passing CI snapshot for that SHA. External credentials, hardware, signing, notarization, stores, registries, and paid services remain `external-pending` until real evidence exists.
- PR references below use the historical APO issue as the durable lookup key because a historical issue can have multiple or superseded PRs. The linked PR state must be re-read before promotion to `verified-ci`.

## Audit conclusions

1. The repository has a substantial tested library surface, but package tests were repeatedly promoted into milestone completion without proving the product entry and composition root.
2. Memory is the largest cross-layer hole. Scoped store and ACL fixtures do not satisfy L2–L4 outcomes.
3. OpenAI, Gemini, Ollama, FallbackRouter, MCP, and WebSearch lack one or more product wiring or real E2E steps.
4. Release fixtures correctly prove contracts but must remain `partial` or `external-pending`.
5. R0–R6 in `10-milestones.md` is the only current milestone baseline. Historical L labels remain traceability clues.

## Promotion checklist

For every row: link the exact spec and entry; identify the composition root; add direct and boundary E2E tests; record PR/DCO/changeset and merged SHA; bind local and CI results to that SHA; and keep paid calls, credentials, hardware, signing, publication, and approval as explicit external gates.
